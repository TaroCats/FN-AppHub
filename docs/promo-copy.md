## 主文案（长版，用于公众号 / 论坛 / V2EX 发布）

### 你的 NAS，还缺一块「桌面」

玩 NAS 到第三年，你大概会经历这样一段路。

第一台机器装了三五个容器，qBittorrent 下载、Jellyfin 看片，一切都还很清爽。后来装了 Immich 管照片，Navidrome 听歌，Portainer 看容器，AdGuard 挡广告，Vaultwarden 存密码，Syncthing 同步文件……再往后，你自己都记不清哪个端口是哪个了。

于是收藏夹里躺了一排 `192.168.1.10:8xxx`，每个星期都要对着 Docker 面板重新数一遍端口。手机想在外网看一眼下载进度，得先翻聊天记录找那条「端口对照表」。

**AppHub 要做的事很简单：把这个入口还给你。**

### 装完就能用，不用先配置

第一次打开 AppHub，它会读一遍 Docker 的端口映射，把所有正在对外提供 Web 服务的容器扫出来，**自动收录**并分好组——最多一次带进 24 个。

不是冷冰冰的 `container-7f3a`，它会认出这是 qBittorrent（下到「下载」组），那是 Jellyfin（进「影音」组），还有 Immich、Navidrome、Portainer、Vaultwarden 等 35 款常见应用，连图标配色和分组都替你想好了。剩下没认出来的，也能手动添加，名称、地址、分组、备注随便填。

打开面板，看到的就是一墙整齐的应用卡：品牌色图标、在线/离线小圆点、端口和备注一目了然。

### 多窗口，才是 NAS 该有的样子

以前点开一个应用，就只能看这一个。想看下载速度的同时盯一眼监控曲线？只能切标签页，来回跳。

**v1.0.27 起，内嵌浏览变成了一个真正的工作区：**

- **同时开多个应用**，顶部标签栏按打开顺序排列，点一下就切过去
- **默认全屏**，当前应用占满整个画面，一个应用专心用
- **分屏**：所有窗口平铺。两个应用左右各半；三个应用左二右一；四个 2×2 四宫格。边看监控边操作下载，一屏搞定
- **缩小**：窗口变成可拖动、可缩放的浮动窗。拖标题栏挪位置，拖右下角改大小，点哪个哪个自动浮到最前，双击标题栏回到全屏

每个窗口都有自己的刷新、全屏、新窗口打开和关闭按钮。哪个应用加载慢、或者站点不让内嵌，只在那一个窗口里提示，不会拖累其他已经正常显示的应用。

布局会被记住——你上次用的是分屏，下次进来还是分屏。

### 不绕路的技术选择

很多同类方案会在中间架一层反向代理，改写页面、剥响应头、注入补丁。听起来聪明，用起来问题很多：登录态丢了、WebSocket 断了、绝对路径资源 404、前端路由错位。

AppHub 从 1.0.22 起把这条路彻底砍了。**应用地址就是它自己的 `http://局域网IP:端口`，内嵌的 iframe 和新标签页打开的是同一个地址**，中间没有任何东西。

这意味着：
- 不用域名，不用改 hosts，不用管 mDNS 解析慢
- 登录状态是应用自己的，AppHub 不读也不碰你的 Cookie
- 应用怎么跑，在这里就怎么跑

换网段或者 NAS 改了 IP？在顶部「访问地址」里改一次，所有应用地址批量重写，不用逐个编辑。

### 它不做什么

说清楚边界，比吹能力更让人放心：

- **不会启停你的容器**。只读挂载 `docker.sock`，只做查询
- **没有账号体系**，依赖飞牛应用中心入口的访问控制。要外网访问，请在飞牛「远程访问 / 反向代理」侧加认证
- **不绕过站点限制**。少数站点设了 `X-Frame-Options: DENY`，浏览器就是不让内嵌——这类请用「新窗口打开」，这属于站点自己的策略
- **数据就是一个 SQLite 文件**。备份 `apphub.db` 就是备份全部访问列表，升级覆盖安装数据不丢

### 三条命令就能装

**方式一：FnDepot 第三方源（推荐，能自动更新）**

打开 FnDepot → 设置 → 外部应用源 → 添加源，填：

```text
https://github.com/TaroCats/FN-AppHub
```

同步后就能看到「应用聚合中心」，以后有新版本会直接提示升级。

**方式二：手动装 fpk**

去 [Releases](https://github.com/TaroCats/FN-AppHub/releases) 下载 `apphub_x.y.z.fpk`，飞牛桌面 → 应用中心 → 右上角「…」→ 手动安装。装完桌面就会出现图标。

> 需要 9080 端口空闲。装完图标点不动？`ss -lntp | grep 9080` 看看谁占了。

### 关于它

AppHub 是给飞牛 fnOS 写的原生应用，FastAPI + SQLite + 原生前端，没有构建步骤，没有前端框架，资源占用可以忽略。

它不试图变成万能面板——不管理容器、不监控硬件、不做媒体刮削。它只做一件事：**让你不用再记端口。**

## 核心卖点清单（可拆成卡片 / 图注）

| 卖点 | 一句话 |
| --- | --- |
| 自动收录 | 装完自己读 Docker 端口，最多一次带进 24 个应用 |

## 关键事实备忘（写稿别写错）

- 当前版本 **1.0.27**，安装包约 **101 KB**
- 端口 **9080**，host 网络，需要端口空闲
- 数据目录 `/var/apps/apphub/shares/apphub/data`，库文件 `apphub.db`
- 内置预设 **35 款**（37 条匹配规则，含 qBittorrent / Jellyfin / Emby / Plex / Immich / Navidrome / Portainer / Vaultwarden / Nextcloud 等）
- 首启自动收录上限 **24 个**
- 判重规则：**IP + 端口 + 主页地址**三者全一致才算重复，同端口可以挂不同入口
- 站外/外网访问需自行在飞牛侧加认证，应用本身无账号体系
